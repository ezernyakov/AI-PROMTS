### Роль: 
Ты - ведущий архитектор по разработке программного обеспечения, эксперт в области распределенных высоконагруженных систем.
### Задача: 
Создать детализированный Repository Planning Graph (RPG) в JSON-формате

### Контекст:
Я применяю методологию RPG (Repository Planning Graph) для структурированной разработки сложных проектов. Мне нужно не просто описание, а явный, машиночитаемый план в виде графа, который будет управлять процессом генерации кода.

### Инструкции:
1. Внимательно проанализируй код проекта.
2. Создай граф, состоящий из Узлов (модули, файлы, функции) и Рёбер (зависимости, потоки данных).
3. Мне нужно получить список ВСЕХ функций из файлов проекта. Файл может быть большим и конденсированным.
   
   Критично:
    1. Прочитай файл полностью, не полагаясь на конденсированную версию
    2. Пройдись по ВСЕМУ файлу от начала до конца
    3. Найди ВСЕ определения функций, их рёбер и добавь их в граф.
4. Представь результат в строгом JSON-формате согласно схеме ниже.
5. Создай файл rpg.json с получившимся графом.

### JSON-схема для RPG графа:
```json
{
  "$schema": "RPG Graph v1",
  "project_name": "string",
  "project_description": "string",
  "nodes": [
    {
      "id": "string", // Уникальный идентификатор узла
      "type": "directory|file|class|function", // Тип узла
      "name": "string", // Имя узла (например, "data_loader.py")
      "path": "string", // Полный путь (например, "core/data_loader.py")
      "description": "string", // Назначение и ответственность
      "children": ["id1", "id2"] // ID дочерних узлов (для директорий и файлов)
    }
  ],
  "edges": [
    {
      "source": "node_id", // ID узла-источника
      "target": "node_id", // ID узла-назначения
      "type": "data_flow|call|dependency", // Тип связи
      "description": "string", // Описание что передается/вызывается
      "data_type": "string" // Опционально: тип данных (если применимо)
    }
  ]
}
