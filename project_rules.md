### Контекст
  1. Техническая документация по системе: ai/dev_summary.md
  2. Документация по юнит-тестам: ai/test_summary.md
  3. Для изучения структуры тестируемого кода используй метод Repository Planning Graph (RPG).
    RPG — это граф, где узлы представляют собой компоненты кода (например, классы, функции, модули), а ребра фиксируют семантические связи, потоки данных
    (например, импорты, вызовы, наследование).
    Ссылка на RPG кода сервиса: ai/rpg/rpg.json
  - **ОБЯЗАТЕЛЬНО**: Используй RPG-граф для навигации по коду тестируемого сервиса. Граф содержит все компоненты (классы, функции, модули) и их связи
    (импорты, вызовы, зависимости). Используй поиск по коду в случае, если граф не содержит информацию по какому-либо методу или обнаружено расхождение графа и реализации.
    Обязательно сообщи, если в ходе работы обнаружится расхождение графа и реализации. 
  **Процесс**:
    1. Анализируй граф для поиска релевантных компонентов
    2. Определяй зависимости через ребра графа
    3. Читай только найденные файлы/функции
    4. Экономь токены - не сканируй весь код
