## Требования к плану

### Важно: Проверка полноты ТЗ
Перед составлением плана проанализируй техническое задание на полноту и однозначность. Если есть неясности, противоречия или недостающая информация - ОСТАНОВИ составление плана и задай уточняющие вопросы. Не делай предположений о недокументированном поведении.

### Структура плана
План должен состоять из этапов с подэтапами:
- Этап (## Этап N: Название) - логически завершенная часть работы
- Подэтап (### N.M Название) - конкретное техническое действие

Используй только ## для этапов и ### для подэтапов. Не используй #### или другие уровни.

### Охват плана
План должен включать ТОЛЬКО разработку функционала:
- Создание/изменение классов, интерфейсов, методов
- Добавление полей, параметров, возвращаемых типов
- Интеграцию с SDK и другими компонентами
- Модификацию бизнес-логики

План НЕ должен включать:
- Тестирование (unit, integration тесты)
- Развертывание и деплой
- Написание документации
- Code review
- Настройку CI/CD

### Детализация подэтапов
Каждый подэтап должен содержать:
- Что именно создать/изменить (конкретный класс, интерфейс, метод)
- Где это находится (пакет, модуль)
- Какие поля/параметры добавить с указанием типов
- Какие аннотации применить
- Особенности реализации (обработка null, async, timeout и т.д.)

Используй маркированные списки (начиная с "-") для описания действий в подэтапе.

### Уровень детализации
Будь максимально конкретным:
- Указывай точные названия классов и методов
- Указывай типы полей и параметров (например, `List<String>`, `CompletableFuture<Void>`)
- Указывай конкретные аннотации (например, `@Nullable`, `@Service`)
- Описывай возвращаемые типы методов
- Упоминай особенности (nullable, optional, timeout значения)

НЕ используй абстрактные формулировки типа "реализовать бизнес-логику" или "добавить обработку ошибок" без конкретики.

### Формат вывода
- Используй markdown заголовки ## для этапов, ### для подэтапов
- Используй маркированные списки (-) для перечисления действий
- НЕ включай код - только описание того, что нужно сделать
- Начинай глаголами действия: "Создать", "Добавить", "Изменить", "Вызвать"
- Указывай конкретные имена классов в backticks: `ClassName`
